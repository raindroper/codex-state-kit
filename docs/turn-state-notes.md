# Turn-State 机制

[返回首页](../README.md)

本文说明当前代码行为。早期关于 Token 池、每条请求消耗一个 Token、30 分钟自动失效的实验方案，已不适用于当前实现。

## 获取与缓存

应用使用当前工作目录中的 ChatGPT 凭据，通过所选出站代理向上游 `/responses` 发起轻量请求，从响应头读取 `x-codex-turn-state`。探针使用与 Codex TUI 自洽的 `User-Agent`、`originator`、`version`，每次生成新的 `session_id`，请求体为固定的 `ping/pong` 轻量交互。

- 全局单发获取；每轮只选择一个需要刷新的模型，多个模型按轮次轮询，不产生十路突发。
- 请求强制使用 HTTP/1.1、新连接和 `Connection: close`；认证信息不会跟随重定向。
- 只有 HTTP 200 下长度精确匹配该模型请求开始时绑定长度、前缀正确、时间戳可解析且未超过预取年龄的候选值才会入池；312、未来时间戳和其他长度仅记录后拒绝。
- Token 按模型分别缓存，内存与本地文件同步，启动时尝试恢复；不同模型不可互用。
- 未命中目标长度时 6 秒后重试；连接阶段失败会在同一模型内最多尝试 4 次，每次仍间隔 6 秒。429/503 与连接失败按全局线路退避 30 秒，401 按账号全局冷却 5 分钟；403 只让对应模型冷却 30 秒，其他模型仍可在共享单发与 6 秒间隔约束下继续获取。有可用票据时约每 30 秒巡检。
- 票据超过 35 分钟开始预取，40 分钟后不再注入；预取失败期间仍可使用尚未到 40 分钟的旧票。
- 切换工作目录、出站地址、出站模式或上游配置等会清空缓存并重新获取。

获取成功必须同时满足 HTTP 200、响应头票据合法且匹配该模型当前绑定长度。探测使用账号授权发起真实请求，会消耗上游请求资源，不应视为无成本的本地检查。

## 请求处理

| 流量 | 当前规则 |
| --- | --- |
| HTTP `POST`，路径包含 `/responses` | 仅在客户端已携带 Turn-State 时，用缓存替换 |
| HTTP 首次请求未携带 Turn-State | 保持未携带状态 |
| WebSocket 升级请求 | 返回 426，让 Codex 客户端回退到 HTTP SSE |
| 上游业务响应 | 不进入本地票据池；本次注入的票据仍是当前票且明确返回 312 时，清除对应模型旧票据并唤醒重新获取 |

没有缓存时保留客户端原值。缓存会重复使用，不会按请求消耗；代理层仍会按 HTTP 转发要求处理连接相关头。

## 当前边界

- **首次请求保持无票据**：只有客户端后续已经携带 Turn-State 时才按请求体中的实际模型替换；无法识别模型时保留客户端值。
- **账号快照保持一致**：每个业务请求使用同一份凭据快照完成票据池账号校验和 Kit 鉴权覆盖；客户端原头与当前官方账号不一致时不注入缓存票据。
- **业务响应不进入票池**：真实业务响应中的 Turn-State 只用于日志，不会覆盖后台探针取得的模型票据。
- **代理 URL 不做会话改写**：每次探针使用新 client 和新连接；动态住宅代理是否更换出口由代理供应商决定。
- **长度是项目筛选规则**：界面中的“292”“312/降智”是项目标签，不是模型能力或计算档位的官方指标。

本工具以缓解使用问题为目标，不改变账号套餐、配额或模型本身，也不保证消除上游过载。历史实验中的地区、长度和单题回答差异不足以证明模型能力变化，不能作为稳定效果承诺。
