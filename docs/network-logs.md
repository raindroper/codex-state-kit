# 网络路由日志

[返回首页](../README.md)

主界面不直接铺开请求日志。点击页面底部的「网络日志」可查看当前路径和最近请求。

## 路径摘要

日志窗口分别显示两条独立线路：

- **Token 获取**：State Kit 通过内置 WARP 或手动代理访问 Codex 上游。WARP 行显示最近一次验证到的出口 IP 和地区。
- **业务请求**：Codex 先连接本机代理，再通过独立的上游转发代理或系统默认网络访问 Codex 上游。留空上游转发代理时，进程仍可能受系统或环境代理影响，因此界面不会把该模式标成直连。

两条线路的代理配置互不继承。如果 Token 获取和 Codex 业务请求都要使用同一个手动代理，需要分别填写「Token 获取代理」和「上游转发代理」。`socks5://` 在实际请求中会转换为 `socks5h://`，使上游域名解析也通过 SOCKS 代理完成。

## 请求字段

Token 获取和业务请求都会形成逐次记录。每条记录包含请求时间、用途、方法、路径、模型、传输协议、配置代理、目标 origin、最终响应 origin、TCP peer、HTTP 版本、Turn-State 动作与长度、请求体大小、编码、状态码和收到响应头的耗时。

业务响应在收到响应头后继续记录流生命周期：等待首块、传输中、完成、读取错误或下游取消，以及首块/最后块/完成耗时、块数、字节数、当前静默时间和最大正文静默时间。最大正文静默涵盖响应头到首块、相邻响应块以及末块到结束之间的间隔。时间均从 State Kit 收到本机请求开始计算，因此“响应头耗时”和“流总耗时”是两个不同指标。正在传输的记录会随状态轮询更新。

收到响应头后以上游 `Content-Type` 为准判断是否为 SSE；明确的 JSON 等错误响应按普通 HTTP 记录。请求账号与票据池绑定账号不一致时，Turn-State 动作显示沿用客户端值，不记录任何账号标识。

Token 获取探针固定使用 HTTP/1.1 新连接。每个待刷新模型按逻辑轮次单发；仅连接阶段失败时会在同一模型内有界重试，所有物理请求之间至少间隔 6 秒。因此日志中的一条 `token_fetch` 对应一次真实上游请求，不再出现同轮十路突发。

`TCP peer` 表示本次连接首先到达的网络地址：配置显式 HTTP / SOCKS 代理时通常是代理地址；使用系统默认网络时通常是上游地址或系统代理地址。它不是最终公网出口 IP。

日志最多保留 80 条，只存放在进程内存中，退出应用后清空。为避免并发探测或连续失败淹没业务记录，其中 Token 获取记录最多保留 30 条。点击「复制日志」可复制当前路径摘要和结构化记录。

## 数据边界

网络日志不保存 Authorization、Cookie、API key、代理用户名或密码、Turn-State 原值、请求体、响应体、响应块内容和 URL query。流生命周期只累加时间、块数与字节数。模型与路径会移除控制字符并限制长度。错误仅记录 `connect`、`timeout` 等类别，不复制完整上游错误内容。
